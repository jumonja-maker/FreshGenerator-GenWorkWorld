# Проверка памяти высотного кэша 0.3.3

В незавершённом варианте кэш при первом значении выделял массивы на 2048 ячеек, даже если задача запрашивала лишь несколько высот. Исправлено: начальная таблица имеет 32 ячейки (для маленьких лимитов — не больше удвоенного лимита) и увеличивается только при заполнении наполовину. Логический предел 1024 записи, порядок промахов и момент полного очищения не меняются. Перенос при росте не вызывает новых запросов высот/биомов и сохраняет все биты float.

Добавлены проверки начального размера, каждого расширения, signed zero, отсутствия преждевременного роста при обновлении существующего ключа и невозвращения старого поколения при переразмещении. Локально выполнены 2 000 000 сравнений hit/miss/значения с прежней ограниченной HashMap и ещё 250 000 синтетических обращений через независимый проверяющий объект; расхождений нет. Это НЕ число вызовов внутри Minecraft.

[Измерения выделений памяти](../research/cache-allocation-check-0.3.3.json) выполнены отдельно на OpenJDK 21.0.12.1, по 2048 новых кэшей на размер. Установка мода и серверные проверки используют Java 25. Например, для 8 записей получено 704 байта у HashMap и 600 байт у растущего примитивного кэша; для 128 — 11 328 и 7912 байт. Это суммарные выделения в синтетической проверке, не постоянная занятая память и не процент ускорения игры. FPS, C2ME и DH этим тестом не измеряются.

Воспроизведение из корня репозитория (выходные классы отдельно от игрового JAR):

```sh
mkdir -p build/cache-probes
javac -d build/cache-probes src/core/java/dev/freshgenerator/core/ColumnFloatCache.java src/audit/java/dev/freshgenerator/audit/ForestHeightOracle.java research/checks/CacheAllocationProbe.java research/checks/CacheTraceProbe.java
java -Xmx256m -cp build/cache-probes CacheAllocationProbe
java -Xmx256m -cp build/cache-probes CacheTraceProbe
```
