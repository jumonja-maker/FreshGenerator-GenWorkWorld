# Одинаковые наблюдения в техническом сравнении

Найдено различие оснастки, унаследованное от аудита 0.3.1 → 0.3.2. Только при `FG_REGION_MODE=candidate` общий `BiomeRegionWorldAudit` дополнительно создавал семплер старого нерегионального климата 0.3.1 и сравнивал его с текущим. В исходной фазе `baseline=climate`. Это оправдано в историческом сравнении изменения масштаба биомов, но лишнее и несимметричное действие при техническом сравнении 0.3.2 → 0.3.3 с одинаковыми данными генерации.

Технический скрипт теперь готовит одинаковый scratch-наблюдатель: обе стороны проверяют текущий климат. Меняется только внутреннее условие исторической реконструкции. Поля режима/source/seed, координаты, выборка высот, массивы готовых блоков и контрольные суммы сохраняются. Сам исторический Java-наблюдатель в репозитории не переписан; прежний аудит размеров биомов сохраняет исходное поведение. Шесть дополнительных проверок преобразователя запускаются перед каждым серверным сценарием и не включаются повторно в счётчик 98 тестов основного задания.

Ослаблений условий допуска нет: все 344 файла генерации и опубликованный лесной `.class` должны совпадать с 0.3.2. Стабильные контрольные блоки сравниваются точно; ненаблюдавшееся на той же координате состояние запрещено. Проверки пещерных решений, воды, сохранённых биомов и повторного открытия остаются обязательными.

Не утверждается, что эта асимметрия была единственной причиной девяти отличий отклонённой лесной оптимизации. Эксперимент не возвращён в рабочий мод. Прежняя неудачная выборка остаётся в `research/rejected-candidates`, а вся новая выборка выполняется заново.
