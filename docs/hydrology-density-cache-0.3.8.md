# 0.3.8: повторное использование плотностей без изменения геометрии

База: `6449741860fb0e8daf87ebaad3537b6b2211b5eb`, PR №6. Это продолжение кандидата, не опубликованный выпуск main.

## Причина и изменение

Локальная запись Java Flight Recorder внутри генерации 288 FULL-чанков показала преобладание вычислений шумов и графа плотностей, а не обхода речного графа. Две общие функции `coherent/surface_density` и `coherent/native_cave_body` повторно используются в конечной плотности и горной детализации.

Вокруг каждой добавлена только штатная оболочка `minecraft:cache`. Внутренние выражения, порядок арифметики, разрешение интерполяции, seed, blend-входы, правила структур, параметры рек и озёр не изменены. Кэш принадлежит штатному контексту семплирования, не глобальной карте мира. Игровых runtime-классов и обязательных зависимостей не добавлено.

Пакетная проверка требует ровно эти два прозрачных кэша, исходное тело пещер и прежний точный cap поверхности; изменение внутреннего шума, порога, порядка вычислений или типа интерполяции отклоняется. Это расширение разрешённого изменения ресурсов для конкретных проверяемых оболочек, не произвольное исключение ресурсов из проверки.

## Локальные доказательства

- 318 Java-тестов против реального API Minecraft 26.3, Java 25: все прошли, пропусков нет.
- 196 Python discovery-тестов прошли.
- На пяти настоящих серверах (42, 1337, -20261111, 2037157180504249802, 801086821803359396) сравнение native samplers с их точными необёрнутыми входами дало 1 292 800 совпадений float-битов. Проверены скалярные/объёмные и смешанные запросы, повторное использование объёма, прямой/обратный и параллельный порядок, границы чанков/тайлов и высоты -64..320. Это конечная выборка, не доказательство всех возможных координат.
- `NativeDensityCacheVerifier` подключён к обязательному серверному аудиту поверхности/структур. Его отрицательные тесты отвергают изменение на один ULP, знак нуля и нечисловые значения. Наблюдатель не входит в игровой JAR.
- Локальные игровые пакеты до и после имеют одинаковую инвентаризацию и одинаковые байты всех 70 runtime-классов. Меняются только два JSON и их manifest. Пакетная проверка относительно опубликованной 0.3.6 проходит, включая 37 прежних неизменённых классов.

## Предварительное измерение

Сид 1337, участки 192×192 с началами (224,-800) и (704,-1488), всего 288 FULL-чанков на прогон. Отдельные JVM, 4 активных процессора, Xms512M/Xmx2G; генерация измерена без диагностического чтения блоков и без JFR. Последовательность ABBA, один процесс за раз:

| Прогон | Исходный кандидат, с | С двумя кэшами, с |
|---|---:|---:|
| A1/B1 | 35.370 | 29.593 |
| A2/B2 | 37.842 | 31.218 |
| Среднее | 36.606 | 30.405 |

Примерно -16,9% времени в этой выборке относительно 6449741, не относительно 0.3.7 и не прирост FPS. Эти предварительные пакеты скомпилированы одинаковым локальным javac и отличаются только JSON; это не каноническая Gradle-сборка релиза. Требуются повторные сравнения окончательного пакета и полный CI. RSS всего процесса в четырёх прогонах: 1262800, 1257480, 1236816, 1424940 КиБ; статистически надёжное уменьшение памяти не заявляется.

## Ограничения

Это оптимизация исполнения, не новое изменение формы рек. Она не доказывает клиентскую естественность всех водоёмов. Проверки поведения воды 0/200/1000 тиков, деревень, структур, обычного мира и Distant Horizons не отменяются; прежний успешный CI не выдаётся за проверку новых байтов. Main остаётся нетронутым до завершения приёмки кандидата.
