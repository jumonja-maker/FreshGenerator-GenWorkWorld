# 0.3.8: слияния рек и контроль водных ступеней

Продолжение PR №6. Игровые изменения: `80bac63ab898cd3a58022dfcb7b36e2f25a545d6`. Это кандидат, не опубликованный выпуск main. Предыдущий документ `hydrology-backwater-followup-0.3.8.md` сохраняет исторические результаты старого локального пакета.

## Причина и исправление

Малая входящая река интерполировала свой расход в суммарный расход принимающего узла ещё до слияния. Например, на сиде 1337 поток с Q68 расширялся как принимающая река Q1024, а верхняя часть потока пересекалась с широкой нижней водой возле озера Y68. Теперь входящая связь сохраняет собственные ширину и глубину; общий расход применяется на исходящей связи. Уровень согласуется с расширенным берегом принимающего русла, а не только с центром расчётного узла. Равные по ширине связи не получают лишнюю горизонтальную ступень на каждом узле. Физика и игровые тики не отключены.

## Более строгая приёмка

Помимо отсутствия нового затопления и сохранности источников, отклоняется изменение верхнего уровня более чем на один блок в уже мокрой колонке. Одноблочный переход допускается только внутри прежнего водного следа, явно записывается и должен стабилизироваться к 200 тикам. Это критерий данной конечной выборки, не физический закон. Отрицательные тесты не позволяют скрыть многоблочный подпор существующим источником ниже него.

## Оптимизация и ограничения

Растеризация обходит ограничивающий прямоугольник фактической кривой с консервативным запасом береговой ширины, а не большой прямоугольник вокруг исходных узлов. Постоянные ширина и глубина вынесены из цикла колонок. В 75 парных сценариях ядра совпали водные профили и поправки рельефа до/после одной этой оптимизации. Это не сравнение новой геометрии со старым генератором. Сама оптимизация не является доказательством ускорения Minecraft.

Перед выпуском нужны свежая полная CI-матрица, проверка итогового JAR, измерения производительности и клиентский визуальный обзор. Точные места пользовательских скриншотов без сида/координат не воспроизведены. Не объединять в main только по локальным результатам.
